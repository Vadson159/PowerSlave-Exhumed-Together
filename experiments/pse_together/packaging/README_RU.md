# PowerSlave Exhumed Together — набор П25

Это диагностическая сборка для Windows 10/11 x64. ENet-программа проверяет
связь по LAN/Radmin и моделирует игроков вне игры. Нативные DLL П1/П24 вложены
как замороженные артефакты для разработчика. Переносимый игровой кооп ещё не принят.
Игра, сохранения, Steam, REA, Python и игровые ресурсы в архив не входят.

## Установка и связь

1. Распакуйте ZIP целиком в отдельную доступную для записи папку, например
   `C:\PSE-test`. Не распаковывайте его поверх игры. Администратор не нужен.
   Нужны Windows PowerShell 5.1 и системные Windows DLL; VC++ runtime встроен.
2. Запустите `verify.bat`. Проверяются SHA-256 файлов и схема конфига.
   `friends.json` намеренно редактируемый и не входит в список хешей.
3. Откройте `friends.json` Блокнотом. `bind` — адрес компьютера хоста;
   `host` — адрес хоста для клиента. Для локальной проверки оставьте 127.0.0.1.
   Для LAN укажите частный IPv4, для Radmin — адрес 26.x.x.x.
   `port` — одинаковый UDP-порт 1024..65535 у обоих, по умолчанию 27015.
   `token` — одинаковый пароль сессии. `name` и `participant_id` — разные
   у каждого друга. Для этих трёх строк: 1..32 латинских букв, цифр, `_`, `-`.
   `max_clients`: 1..7, стандартно 1; это ёмкость диагностического прототипа.
   `crash_dumps`: true включает внешний захват аварии, false оставляет только логи.
   Незнакомые поля, неверные типы и публичные адреса отклоняются до запуска.
4. Хост запускает `host.bat`, друг — `client.bat`. При запросе Windows Firewall
   разрешите связь только в нужной частной сети. Скрипты не меняют firewall.
   При использовании Radmin участники должны состоять в одной сети Radmin.
5. У клиента ожидается `Authenticated!`, у хоста `status` показывает P2.
   `stat` печатает RTT/пакеты; `move 1 0`, `shoot` — команды модели вне игры.
   `quit` завершает процесс штатно. Тест на двух ПК этим архивом ещё не проведён.

## Логи и аварии

Каждый запуск создаёт новую папку `logs/<роль>_<UTC>_<ID>/`.
`console.log` — stdout/stderr, `diagnostics.log` — PID, коды исключения и выхода,
`session.json` — роль, результат и версия набора без пароля.
При необработанном исключении дочернего ENet-процесса внешний supervisor
пишет `crash.dmp` (Windows minidump с контекстом исключения). Он не подключается
к KEX. Ошибка записи дампа фиксируется как `crash_dump_failed`; ненулевой exit
сам по себе не доказывает наличие дампа. При закрытии окна дочерний процесс
тоже завершается; для сохранения отчёта используйте `quit`.

Запустите `collect.bat` после выхода обоих процессов. Архив `results_*.zip`
содержит только известные текстовые логи. Пути текущего пользователя/набора и
MAC редактируются; адреса, имена игроков и произвольный текст могут сохраниться.
Просмотрите архив перед отправкой. Конфиг, token и дампы по умолчанию не вложены.
Для добровольного включения дампов: `powershell -NoProfile -ExecutionPolicy Bypass
-File .\friends.ps1 collect -IncludeDumps`. Дамп может содержать приватные данные
процесса и не обезличивается. Самостоятельно отправьте нужный архив разработчику.

Удаление: закройте процессы, сохраните нужные результаты, удалите распакованную
папку. Скрипты не устанавливают службы, драйверы или настройки реестра.

## Нативные артефакты и EXE

Целевой EXE SHA-256:
`b8f131037187ca8d0a282527fb6f55a2012241d5b9dac8bf2038baf35b71a76d`.
`native-reference/` содержит exact frozen SDL2 shim, broker, checker и две
раздельные payload DLL. Их хеши/происхождение перечислены в `provenance.json`.
`symbols.zip` поставляется отдельно для диагностики; игровые ресурсы не включены.
`native-reference/pe-check.exe <путь-к-EXE>` только читает файл, выводит RU/EN
expected/actual SHA (stdout UTF-16LE), возвращает 0 или Win32-код ошибки.
Не копируйте эти DLL в оригинальную Steam-установку и не запускайте KEX через
этот набор. Принятый broker допускает лишь два точных пути рабочего стенда,
изолированный профиль обеспечивает REA по DOC-51/П24. Для native эксперимента
разработчик использует существующий workspace и `tools/p24.py` по его README;
этот архив не выдаёт native permit и не меняет игровые конфиги или хуки.
Нативные логи/дампы KEX остаются в evidence принятого стенда; автоматический
захват дампов KEX и чистая игровая установка друга здесь не аттестованы.

При отказе SHA, повреждённом архиве или неверном конфиге сохраните сообщение,
проверьте `verify.bat` и повторно распакуйте исходный ZIP в новую папку.
Отсутствие `Authenticated!`: проверьте адрес/порт/token, Radmin и firewall;
не отключайте firewall целиком. Порты не пробрасываются, matchmaking отсутствует.
