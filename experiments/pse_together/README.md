# pse_together

Единая кодовая база кооператива: одна DLL (`pse_together.dll`), роль хоста или клиента выбирается переменной
`PSE_ROLE` (`pe-play --role host|client` выставляет её сам).

| Часть | Где |
|---|---|
| Протокол, ENet-воркер, мост потоков | `src/net` (`net_protocol.h` — версия протокола) |
| Сессия хоста (ввод P2, снимки, карта) | `src/session/network_input.cpp` |
| Хост / клиент / точка входа DLL | `src/native/host.cpp`, `client.cpp`, `dll_main.cpp` |
| Прокси игрока хоста на клиенте | `src/native/native_proxy.cpp`, `src/proxy/` |
| Меню, лобби, чат, автокарта | `src/native/ui_native.cpp`, `src/ui/` |
| Загрузчик (SDL2-shim, broker, `pe-play`, защита записи) | `src/loader/` |
| Установка копии игры + `host.bat`/`join.bat` | `tools/p27.py install` |
| Смена мира (Restart Level, чекпоинт) | `worldTransition()` в `client.cpp`, `native_proxy::rearm()` |
| Двери/лифты/платформы и общие ключи (Веха 2) | `src/native/world_sync.{hpp,cpp}`; обвязка: `worldSyncHost()` в `host.cpp`, `Session::worldSync()` в `client.cpp` |

Сборка и тесты — в `AGENTS.md`. Подробности удалённых форков — в git-теге `pre-collapse`.

### Как устроена синхронизация мира (Веха 2)

Обе стороны крутят полный мир локально, поэтому дверь не «двигаем вершины», а повторяем нативный вызов движка
`kexActorFactory::SpawnMover(className, type, sector)` (RVA `0x1d4e20`; `UseWallSpecial` 0x1bccb0 и `EnterSectorSpecial` 0x1bea70
зовут его для дверей `kexSlaveMoverDoor`, лифтов, платформ). Хук кладёт вызовы игры в очередь, сессия шлёт их второй стороне:
хост → клиент `MSG_WORLD_EVENT_CONFIRM` (`EvMover`, `EvKeys`), клиент → хост `MSG_INTERACTION_REQUEST` (`ReqMover`, `ReqKeys`);
кодирование полей — в `world_sync.hpp`. Повтор помечен флагом, чтобы не было эха; уже движущийся сектор (флаг `SF_SPECIAL`) движок
отвергает сам. Ключи (`Player+0x98`, 4 бита) — объединение P1|P2|клиент: получатель повторяет подбор нативным `OnTouch` по актору-ключу
(звук, надпись, вспышка, удаление), иначе пишет бит напрямую.

Ввод клиента (v1.14, `MsgInputCommand`): оси forward/right, кнопки (`ButtonFlags`: атака, прыжок, E, оружие +/-), `yaw/pitch` и
собственные `pos/sector` клиента. Клиент симулирует себя сам; хост на каждом тике ставит P2 в позу клиента (нативный телепорт:
позиция, `LinkSector`, кэш пола/потолка, сброс интерполянтов — `world::teleport`) и подаёт его кнопки в нативный ввод P2. E в игре —
однокадровый импульс (`+use`), поэтому клиент берёт кнопки сразу после `Commands` и держит E несколько отсчётов.

Враги: хост раз в 3 тика шлёт `MSG_WORLD_SNAPSHOT` (канал 3, без гарантий): spawn id (+0x180), позиция, скорость, угол, hp, состояние ИИ
(+0x1b8), сектор, смещение анимации в дефиниции актора (указатель +0x108 → поле дефиниции). Клиент подменяет тик ИИ (`0x194ce0`) базовым
тиком актора (`0x19f2d0`), игнорирует реакцию ИИ на урон (`0x195050`) и применяет снимок (`ChangeAnim 0x1a1170` при смене анимации).
Без снимков дольше 1.5 с ИИ клиента работает как раньше. Урон врагам наносит P2 на хосте (атака клиента -> атака P2).

Дымовая проверка без игрока у двери: `PSE_DEBUG_MOVER[_CLIENT]="auto"|"класс,type,сектор"`, `PSE_DEBUG_KEY[_CLIENT]=биты`
(переменные окружения, читаются только в `world_sync`; `tools/smoke.py` их наследует, итог — события `world_*` в `native_*.jsonl`).
Ещё: `PSE_DEBUG_TELEPORT_CLIENT="x,y,yaw"` (поставить клиента в точку), `PSE_DEBUG_ENEMY=<id>` (журнал врага на обеих сторонах),
`PSE_DEBUG_KILL=<id>` (хост убивает врага). Сценарии `smoke.py`: `SMOKE_INPUT=1` (поворот, боком, прыжок, E у двери, атака),
`SMOKE_ENEMY=1`. Дверь TOMB: сектор 33 (x 0, y -1250, взгляд `yaw=3.14159` на север), враг id 7 — сектор 47.

### Бой (Веха 3)

Здоровье своего игрока клиента — решение хоста: `applyHostHealth` сравнивает `health` из снимка слота клиента с локальным `Actor+0x17a` и
вызывает нативный `Damage 0x1a1370` на разницу (вспышка, звук, смерть), хук `Damage` глушит прочий локальный урон по своему актору.
Тот же хук на обеих сторонах блокирует урон Puppet → Puppet (дружественный огонь). Отладка боя в `tools/smoke.py`: `SMOKE_COMBAT=1`
(`PSE_DEBUG_PULL_ENEMY=id,дист` + `PSE_DEBUG_PULL_FILE`, `PSE_DEBUG_TELEPORT=x,y,yaw` — убрать хост с линии), `SMOKE_RESPAWN=1`
(`PSE_DEBUG_KILL_P2=<тик>`), `SMOKE_MENU=1`, `SMOKE_NOWALK=1`; атака в смоуке — клавиша F (`tools/smoke_kexengine.cfg`).
