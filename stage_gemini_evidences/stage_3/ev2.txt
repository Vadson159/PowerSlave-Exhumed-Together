### Архитектурный отчёт: Жизненный цикл смерти монстров в PowerSlave Exhumed (KEX Engine 2022)

### 1. Что происходит при падении здоровья до 0 или ниже (порог расчленения)

Функция нанесения урона: **`0x1401a1370`** (`kexActor::InflictDamage`).  
Сигнатура: `void InflictDamage(kexActor* victim, kexActor* inflictor, int damageType, short damageAmount)`

```c
// Дизассемблированная логика 0x1401a1370:
if ((victim->flags & 0x20) != 0) { // AF_SHOOTABLE (0x20)
    victim->flashTicks = 1;        // +0x134 = 1
    victim->flags |= 0x10;         // AF_FLASH (0x10)
    
    // Проверка: если уже играет анимация смерти — игнорировать урон
    if (victim->curAnim != def->deathAnim && 
        victim->curAnim != def->deathWaterAnim && 
        victim->curAnim != def->gibAnim) 
    {
        if (damageType == 2) FUN_1401a0c70(victim); // Огонь / лава

        if (victim->health > 0) {
            victim->health -= damageAmount; // +0x17a (int16)
            
            // vtable[9] (+0x48): OnDamage (kexSlaveAI::OnDamage -> 0x140195050)
            victim->vtable->OnDamage(victim, inflictor);

            if (victim->health < 1) { // Здоровье <= 0
                // Формула порога расчленения (Gib Threshold):
                int gibThreshold = -2 - (def->maxHealth >> 4); // def + 0x50: maxHealth
                bool isGib = (victim->health < gibThreshold);
                
                // Тип урона 1 (взрыв) или 2 (разрыв) принудительно вызывает расчленение:
                if (damageType == 1 || damageType == 2) {
                    isGib = true;
                }

                // Снятие флага уязвимости (больше урон не принимается)
                victim->flags &= ~0x20; // flags &= ~AF_SHOOTABLE

                // Выбор целевой анимации смерти:
                uintptr_t anim = def->deathAnim; // def + 0xb8
                if ((victim->flags & 0x400) && def->deathWaterAnim != 0) { // 0x400: AF_INWATER
                    anim = def->deathWaterAnim; // def + 0xc0
                } else if (isGib && def->gibAnim != 0) {
                    anim = def->gibAnim; // def + 0xc8
                }

                // 0x1401a1170: Установка анимации и немедленное исполнение Action-хуков кадра 0
                FUN_1401a1170(victim, anim);

                // vtable[10] (+0x50): OnDeath
                victim->vtable->OnDeath(victim, inflictor);
            }
        }
    }
}
```

#### Ключевые выводы по порогу гибели:
1. **Порог расчленения:** $-2 - \lfloor\frac{\text{maxHealth}}{16}\rfloor$. Если конечное здоровье ниже этого значения либо тип урона `damageType == 1` (взрыв) / `damageType == 2` (критический/лавовый), активируется ветка расчленения.
2. **Флаги и состояние:** При гибели здоровье обнуляется (`+0x17a <= 0`), флаг уязвимости `0x20` (`AF_SHOOTABLE`) снимается в `+0x16c`, а в `kexSlaveAI::OnDamage` (`0x140195050`) стейт переводится в `AIS_DEAD` (`+0x1b8 = 5`).

### 2. Мумии: Анимация падения vs разрыв на куски (`mummy_death`)

В ходе анализа файлов определений монстров (`res/defs/actors/monsters/mummy.txt`) и анимационных скриптов (`res/sprites/monsters/mummy_anim.txt`) выявлен критический факт:

> [!IMPORTANT]
> **У Мумии (и большинства регулярных монстров в PowerSlave Exhumed) ВООБЩЕ НЕТ анимации падения трупом.**  
> В оригинальном дизайне мумии при гибели всегда разрываются на куски бинтов и плоти. Единственная зарегистрированная анимация смерти у мумии — это `monsters/mummy_death`. Длинные анимации падения трупом (30 кадров) присутствуют только у боссов (Сет `set_death`, Селкис `selkis_death`).

#### Как работают осколки (Gibs):
Спавн осколков **встроен прямо в анимационную последовательность** `mummy_death`:
```text
mummy_death
{
    frame
    {
        action A_GibDeath(0.0)                                          // 1. Спавн крови/мяса Fx_Gibs01
        action A_MummyDeath()                                           // 2. Звук смерти (mumdeath01..03.wav)
        action A_TossActor("Obj_Mummy_Gib01", 0, 0, 32, 8, 8, 4, 16)    // 3. Вызов cActorFactory->Spawn
        action A_TossActor("Obj_Mummy_Gib02", 0, 0, 32, 8, 8, 4, 16)
        action A_TossActor("Obj_Mummy_Gib03", 0, 0, 32, 8, 8, 4, 16)
        action A_TossActor("Obj_Mummy_Gib03", 0, 0, 32, 8, 8, 4, 16)
        action A_TossActor("Obj_Mummy_Gib04", 0, 0, 32, 8, 8, 4, 16)
        action A_TossActor("Obj_Mummy_Gib04", 0, 0, 32, 8, 8, 4, 16)
        action A_Destroy()                                              // 4. Вызов actor->Remove() (0x1401a02b0)
        delay 1
    }
}
```

- Осколки (`Obj_Mummy_Gib01..04`) — это легковесные временные объекты (`expires 1`), спавнящиеся нативным `cActorFactory->Spawn`. Они разлетаются по физике со случайным импульсом, постепенно уменьшаются в размерах (`scale -= scale / 32`) и сами удаляются движком.
- Сам монстр на этом же 0-м кадре исполняет действие `A_Destroy()`, которое вызывает нативный `kexActor::Remove()` (`0x1401a02b0`).

### 4. Рекомендованный протокол исполнения (Вариант Б)

Для клиента безопасным и визуально идентичным синглплееру решением является **Вариант Б** с заполнением минимального набора флагов.

#### Точный адресный вызов на клиенте:

1. **Обнулить здоровье и снять флаг уязвимости:**
   ```cpp
   // Снимаем AF_SHOOTABLE (0x20), чтобы предотвратить локальные коллизии урона
   *(uint32_t*)((uintptr_t)actor + 0x16c) &= ~0x20;
   *(int16_t*)((uintptr_t)actor + 0x17a) = 0; // Health = 0
   ```

2. **Перевести AI в состояние смерти:**
   ```cpp
   // AIS_DEAD = 5 (предотвращает тики логики преследования/атаки на клиенте)
   *(int32_t*)((uintptr_t)actor + 0x1b8) = 5;
   ```

3. **Получить указатель на анимацию смерти из `ActorDef`:**
   ```cpp
   uintptr_t actorDef = *(uintptr_t*)((uintptr_t)actor + 0x170); // def (+0x170)
   
   // Смещения в ActorDef:
   // +0xb8: deathAnim (стандартная смерть / разрыв мумии)
   // +0xc0: deathWaterAnim (смерть в воде)
   // +0xc8: gibAnim (принудительный разрыв, если задан отдельно)
   uintptr_t targetAnim = *(uintptr_t*)(actorDef + 0xb8);
   if (bInWater && *(uintptr_t*)(actorDef + 0xc0) != 0) {
       targetAnim = *(uintptr_t*)(actorDef + 0xc0);
   }
   ```

4. **Вызвать функцию смены стейта / анимации (`0x1401a1170`):**
   ```cpp
   typedef void (*t_ChangeAnim)(void* actor, uintptr_t anim);
   t_ChangeAnim ChangeAnim = (t_ChangeAnim)0x1401a1170;
   
   ChangeAnim(actor, targetAnim);
   ```

#### Что произойдет в результате этого вызова:
- Функция `0x1401a1170` запишет `actor->curAnim = targetAnim` (`+0x108`) и сбросит таймеры.
- Немедленно выполнятся все действия первого кадра анимации:
  1. Сыграет звук мумии `A_MummyDeath()`.
  2. Нативная фабрика спавнит разлетающиеся куски `Obj_Mummy_Gib01..04`.
  3. Вызовется `A_Destroy()`, который безопасно вызовет `0x1401a02b0` (`kexActor::Remove()`), выставив флаг `bStale = 1` (`actor + 0x40`) и скрыв актор.
- Память монстра корректно уйдёт в нативную removal-queue (`0x140af3380`) и очистится сборщиком мусора KEX на границе тика без каких-либо повисших указателей (UAF).
