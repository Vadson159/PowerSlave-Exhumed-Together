# Отчёт реверс-инжиниринга: Механика ключей и инвентаря в PowerSlave Exhumed (KEX Engine 2022)

---

## 1. Проверяемая рабочая гипотеза

1. **Хранилище инвентаря ключей**:
   * Состояние ключей хранится в структуре игрока `kexPlayer` по смещению **`+0x98`** в виде 16-битного битового поля (`int16_t keys`).
   * В игре задействованы младшие 4 бита (маска `0x000F`):
     * **Бит 0 (`0x01`)** — **Symbol of Power** (`Key_Power`, Amun Key, `$str_112` / `$str_116`)
     * **Бит 1 (`0x02`)** — **Symbol of Time** (`Key_Time`, Time Key, `$str_113` / `$str_117`)
     * **Бит 2 (`0x04`)** — **Symbol of War** (`Key_War`, Set Key, `$str_114` / `$str_118`)
     * **Бит 3 (`0x08`)** — **Symbol of Earth** (`Key_Earth`, Earth Key, `$str_115` / `$str_119`)

2. **Обработка физического подбора**:
   * При физическом контакте сферы коллизии игрока (`kexPuppet`) с touchable-актором движок (`TraceSphere`) вызывает виртуальный метод `actor->OnTouch(instigator)` (8-й слот vtable).
   * Для класса `kexSlavePickupKey` этот слот указывает на функцию **`0x1401d8a00`**.
   * Метод `kexPlayer::GiveKey(bits)` в KEX 2022 полностью **заинлайнен** компилятором внутрь `0x1401d8a00`.
   * После установки бита вызывается базовая функция **`kexPickup::OnTouch` (`0x1401d8360`)**, которая проигрывает звук, выводит HUD-сообщение, мигает экраном, помечает ключ собранным в битовой карте уровня и удаляет актор из мира.

## 2. Точные адреса и смещения (ImageBase: `0x140000000`)

| Элемент / Функция | Адрес (VA) | Описание |
| :--- | :--- | :--- |
| `kexSlavePickupKey` TypeDescriptor | `0x140a517d8` | RTTI имя `.?AVkexSlavePickupKey@@` |
| `kexSlavePickupKey` COL | `0x140547c38` | Complete Object Locator |
| `kexSlavePickupKey` vtable | `0x14052c998` | Таблица виртуальных методов |
| **`kexSlavePickupKey::OnTouch`** | **`0x1401d8a00`** | **Слот vtable[8]** (`0x14052c9d8`). Физический подбор ключа |
| **`kexPickup::OnTouch`** (базовый) | **`0x1401d8360`** | Общий обработчик звука, HUD-сообщения, вспышки и `Remove()` |
| `kexPlayer::Keys()` (getter) | `0x1401ae0c0` | Возвращает `&player->keys` (`LEA RAX, [RCX + 0x98]; RET`) |
| `CheckDoorTrigger` | `0x1401bccb0` | Проверка ключа при взаимодействии с дверью/триггером |
| `kexActor::Remove` | `0x1401a1090` | Удаление актора из симуляции мира |
| `kexPuppet::PlaySound` | `0x1401d3b30` | Воспроизведение звука от лица актора |
| `PlayLoop` singleton | `0x140a43e20` | Указатель на синглтон локального цикла игры / HUD |

### Смещения структур

* **`kexActor`**:
  * `+0x16c` — флаги актора (`flags`, маска `AF_SOLID=0x2`, `AF_TOUCHABLE=0x100`).
  * `+0x170` — указатель на дефиницию (`definition*`).
  * `+0x180` — уникальный ID спавна на уровне (для bitset собранных предметов).
* **`definition` актора ключа**:
  * `+0x13c` — тип ключа `keyType` (`0..3`).
  * `+0xf8` / `+0x100` — путь к звуку подбора (`pickupSound`, `"sounds/keypickup.wav"`) и длина строки.
  * `+0x110` / `+0x118` — строковый токен сообщения (`pickupMessage`, `"$str_112"`..`"$str_115"`) и длина строки.
* **`kexPuppet`** (кукла игрока, `instigator`):
  * `+0x17a` — здоровье (`short health`).
  * `+0x1b8` — указатель на владельца `kexPlayer*` (`Owner()`).
* **`kexPlayer`**:
  * `+0x90` — `uint32_t artifacts` (маска артефактов).
  * `+0x94` — `uint32_t abilities` (маска способностей).
  * **`+0x98` — `int16_t keys` (битовая маска сюжетных ключей)**.
  * `+0x9a` — `uint16_t questItems` (детали передатчика).

## 3. Ассемблерный анализ

### 3.1. Физический подбор и взвод бита (`0x1401d8a00`)

```x86asm
; RCX = this (kexSlavePickupKey*)
; RDX = instigator (kexPuppet*)
0x1401d8a00: MOV qword ptr [RSP + 0x10], RBX
0x1401d8a05: PUSH RDI
0x1401d8a06: SUB RSP, 0x20
0x1401d8a0a: CMP qword ptr [RCX + 0x170], 0x0       ; this->definition != nullptr
0x1401d8a12: MOV RDI, RDX                           ; RDI = puppet (instigator)
0x1401d8a15: MOV RBX, RCX                           ; RBX = this
0x1401d8a18: JZ 0x1401d8ab5                         ; выход, если нет дефиниции
...
; Проверка RTTI: instigator->InstanceOf(&kexPuppet::info)
0x1401d8a4f: MOV ECX, dword ptr [0x140a46128]      ; TypeId kexPuppet
0x1401d8a55: CMP dword ptr [RAX + 0x8], ECX
0x1401d8a58: JZ 0x1401d8a6e                         ; совпало -> переход к логике сбора
...
; --- ВЫСТАВЛЕНИЕ БИТА В МАСКЕ (заинлайненный GiveKey) ---
0x1401d8a6e: CMP word ptr [RDI + 0x17a], 0x0        ; instigator puppet health > 0?
0x1401d8a76: JLE 0x1401d8ab5                        ; мертв -> выход
0x1401d8a78: MOV RCX, qword ptr [RBX + 0x170]       ; RCX = this->definition
0x1401d8a7f: MOV EDX, 0x1                           ; EDX = 1
0x1401d8a84: MOV R8, qword ptr [RDI + 0x1b8]        ; R8 = puppet->Owner() (kexPlayer*)
0x1401d8a8b: MOV ECX, dword ptr [RCX + 0x13c]       ; ECX = definition->keyType (0..3)
0x1401d8a91: SHL EDX, CL                            ; EDX = 1 << keyType
0x1401d8a93: MOVSX ECX, word ptr [R8 + 0x98]        ; ECX = player->keys
0x1401d8a9b: TEST EDX, ECX                          ; Ключ уже есть в инвентаре?
0x1401d8a9d: JNZ 0x1401d8ab5                         ; Если да -> выход (ключ не подбирается повторно!)
0x1401d8a9f: OR CX, DX                              ; CX = keys | (1 << keyType)
0x1401d8aa2: MOV RDX, RDI                           ; RDX = instigator (puppet)
0x1401d8aa5: MOV word ptr [R8 + 0x98], CX           ; ЗАПИСЬ: [Player + 0x98] = CX
0x1401d8aad: MOV RCX, RBX                           ; RCX = this
0x1401d8ab0: CALL 0x1401d8360                       ; CALL kexPickup::OnTouch(instigator)
0x1401d8ab5: MOV RBX, qword ptr [RSP + 0x38]
0x1401d8aba: ADD RSP, 0x20
0x1401d8abe: POP RDI
0x1401d8abf: RET
```

### 3.2. Базовый обработчик подбора (`0x1401d8360`)

```x86asm
; 1. Звук подбора: instigator->PlaySound(pickupSound)
0x1401d838b: MOV RDX, qword ptr [RDX + 0xf8]        ; "sounds/keypickup.wav"
0x1401d8392: XOR R8D, R8D
0x1401d8395: MOV RCX, RAX                           ; RCX = instigator (puppet)
0x1401d8398: CALL 0x1401d3b30                       ; instigator->PlaySound(...)

; 2. Вывод сообщения: PlayLoop->Print(localizedMessage)
0x1401d83ae: MOV RAX, qword ptr [0x140a43e20]       ; local PlayLoop vtable
0x1401d83b5: MOV RDX, qword ptr [RDX + 0x110]       ; "$str_112" ("Symbol of Power")
0x1401d83bc: MOV RBX, qword ptr [RAX + 0x18]        ; PlayLoop::Print
0x1401d83c0: CALL 0x1400b92a0                       ; GetLocalizedString
0x1401d83c5: MOV RDX, RAX
0x1401d83c8: LEA RCX, [0x140a43e20]
0x1401d83cf: CALL RBX                               ; Print to HUD

; 3. Фиксация подбора в битовой карте уровня:
0x1401d8430: BTS EAX, EBX                           ; LevelCollectedBitset[spawnId >> 3] |= (1 << (spawnId & 7))

; 4. Снятие флагов коллизии:
0x1401d8435: AND dword ptr [RDI + 0x16c], 0xfffffefd ; flags &= ~(AF_SOLID | AF_TOUCHABLE)

; 5. Золотая вспышка экрана:
0x1401d8448: MOV RAX, qword ptr [0x140a43e20]
0x1401d8456: CALL qword ptr [RAX + 0x28]            ; PlayLoop::PickupFlash()

; 6. Удаление актора из мира:
0x1401d845c: CALL 0x1401a1090                       ; kexActor::Remove()
```

### 3.3. Проверка ключа дверью (`0x1401bccb0`)

```x86asm
0x1401bcdc8: CALL qword ptr [RAX + 0xa8]            ; получение локального kexPlayer* в RAX
0x1401bcdce: MOVSX R8D, word ptr [RBX]              ; тип двери/триггера (3..6)
0x1401bcdd2: MOVSX EAX, word ptr [RAX + 0x98]       ; EAX = player->keys
0x1401bcdd9: LEA ECX, [R8 - 0x3]                    ; индекс ключа (3->0, 4->1, 5->2, 6->3)
0x1401bcddd: MOVZX EDX, CL
0x1401bcde0: BT EAX, EDX                            ; Bit Test: (keys & (1 << index)) != 0 ?
0x1401bcde3: JC 0x1401bcd98                         ; Если бит установлен -> переход к открытию двери!
; Иначе -> форматирование строки "$str_{116 + index}" ("You Need the Symbol of ...") и выход
```

## 4. Локальность звука, сообщений и эффектов

1. **Звук подбора**: 
   * Вызывается через `instigator->PlaySound(sound)`. 
   * Источником звука является кукла игрока (`kexPuppet`). 
   * Звучит в 3D-пространстве мира от позиции поднявшего игрока.
2. **HUD-сообщение (`PlayLoop->Print`)**:
   * Вызывается напрямую через синглтон `[0x140a43e20]`. 
   * **Строго локально**: отображается только на экране того процесса игры, где был вызван `0x1401d8360`.
3. **Вспышка экрана (`PlayLoop->PickupFlash`)**:
   * Вызывается через синглтон `[0x140a43e20]`.
   * **Строго локально**: окрашивает вьюпорт только локального игрока.
4. **Удаление актора (`Remove`)**:
   * Происходит только в памяти того процесса, где сработал физический `OnTouch`.

## 5. Ответ на вопрос по синхронизации через P7 (Рекомендации для C++ мода)

> **Вопрос**: Достаточно ли хосту просто перезаписать поле `[Client_Player + 0x98]` через уже существующий сетевой снапшот состояния игрока (P7)?

### Вердикт: **Для открытия дверей — ДА, достаточно. Но для корректного мира — НЕТ, требуется обработка актора.**

### Подробный анализ:

1. **Двери и инвентарь (Работает сразу)**:
   * Проверка двери в `0x1401bccb0` читает **исключительно** поле `[Client_Player + 0x98]`.
   * В кодовой базе мода в `self_native_p16.cpp` (строки 441–444) уже реализована запись:
     ```cpp
     if (ok && before.keys != desired.keys) {
         auto* ref = keyReference(); // 0x1401ae0c0 -> player + 0x98
         if (ok) { *ref = static_cast<std::int16_t>(desired.keys); }
     }
     ```
   * Как только хост передаёт снапшот с обновлённым `keys`, клиент моментально получает возможность открывать любые двери, требующие этот ключ, а меню инвентаря (`kexInventoryMenu`) начинает рисовать зажжённую иконку ключа.

2. **Проблема с физическим актором ключа в мире клиента («Ключ-призрак»)**:
   * Если хост подобрал ключ на своей стороне, актор ключа удалился (`Remove()`) на хосте.
   * Но в мире клиента этот актор **продолжает стоять на постаменте**.
   * Если клиент подойдёт к ключу, сработает `0x1401d8a00`. Ассемблер выполнит:
     ```x86asm
     0x1401d8a9b: TEST EDX, ECX   ; EDX = 1 << keyType, ECX = player->keys
     0x1401d8a9d: JNZ 0x1401d8ab5  ; Ключ уже есть в инвентаре -> ВЫХОД
     ```
   * В результате клиент проходит сквозь ключ, метод выходит без вызова `0x1401d8360`:
     * Ключ **не исчезает** (остаётся вечно висеть на карте).
     * Звук и вспышка не проигрываются.

### Архитектурная рекомендация для C++ мода:

В кооперативном режиме PowerSlave ключи должны быть **общими (Team Shared Keys)**:

1. **На стороне Host**:
   * Хост собирает ключи от всех игроков: `SharedKeys = Host_Player->keys | Client1_Player->keys | ...`
   * Хост транслирует `SharedKeys` всем клиентам в пакете P7.
2. **На стороне Client при изменении маски `keys`**:
   * При получении нового бита ключа через P7 (например, `(new_keys & ~old_keys)`):
     1. Локально на клиенте найти актор типа `kexSlavePickupKey` с соответствующим `keyType` и вызвать для него удаление:
        ```cpp
        // Снять флаги коллизии и удалить актор, чтобы он не висел призраком
        actor->flags &= ~(0x2 | 0x100); // ~(AF_SOLID | AF_TOUCHABLE)
        reinterpret_cast<void(__fastcall*)(void*)>(g.base + 0x1a1090)(actor); // Remove()
        ```
     2. (Опционально) Воспроизвести для клиента локальный эффект подбора:
        ```cpp
        // Вспышка экрана и уведомление о том, что напарник подобрал ключ
        reinterpret_cast<void(__fastcall*)(void*)>(*reinterpret_cast<void**>(g.base + 0xa43e20) + 0x28)(
            reinterpret_cast<void*>(g.base + 0xa43e20)
        );
        ```
