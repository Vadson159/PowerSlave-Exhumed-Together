### Анализ механизма смены уровня в PowerSlave Exhumed (KEX Engine 2022)

---

### 1. Точный адрес и сигнатура функции смены уровня

В 64-битном бинарнике `anubis_Shipping_Steam_x64.exe` (ImageBase = `0x140000000`) функция инициализации смены карты campaign-режима:

* **Функция:** `kexSlaveGameInstanceLocal::ChangeMap`
* **RVA:** `0x1b54d0`
* **VA:** `0x1401b54d0`
* **Виртуальный слот:** `vftable + 0x88` (слот [17] виртуальной таблицы `kexSlaveGameInstanceLocal::vftable` по адресу `0x14052ad08`).
* **Экземпляр `GameInstance`:** синглтон расположен в секции `.data` по адресу `0x140af33a0` (RVA `0xaf33a0`).
* **Сигнатура (MSVC x64 __fastcall):**
  ```cpp
  void __fastcall kexSlaveGameInstanceLocal::ChangeMap(void* thisPtr, const char* mapName);
  ```
  * `RCX` (`thisPtr`): указатель на синглтон `GameInstance` (`0x140af33a0`).
  * `RDX` (`mapName`): указатель на null-terminated ASCII-строку пути к карте (например, `"maps/KARNAK.MAP"`).

#### Дизассемблирование `0x1401b54d0`:
```nasm

0x1401b54d5: push  rdi
0x1401b54d6: sub   rsp, 0x20
0x1401b54da: mov   dword ptr [rcx + 0x28], 4       ; GameInstance + 0x28 (fadeRequestedState) = 4 (GS_CHANGELEVEL)
0x1401b54e1: mov   rbx, rcx                       ; rbx = GameInstance
0x1401b54e4: mov   rcx, qword ptr [0x140ae90f8]   ; Audio/Timer subsystem
0x1401b54eb: mov   rdi, rdx                       ; rdi = mapName
0x1401b54ee: xorps xmm2, xmm2

0x1401b54f6: mov   rax, qword ptr [rcx]
0x1401b54f9: call  qword ptr [rax + 0x20]         ; Старт затухания экрана и звука
```

### 2. Триггер перехода и определение следующей карты

#### Триггер выхода: `kexSlaveTravelObject`
Объекты перехода (`Obj_Camel`, `Obj_WarpPryamid`, платформы выхода) принадлежат классу `kexSlaveTravelObject` (`vftable` = `0x140530588`):
* **Обработчик касания (`OnTouch`):** `0x1402072e0` (RVA `0x2072e0`, метод `vftable[8]`).
* При касании игроком (`kexPuppet`) триггер проверяет поле `mapDestination` (`+0x1b8`):

1. **Если `mapDestination >= 0` (статический переход):**
   * Индекс карты берется прямо из свойства объекта (распарсенного при спавне в `0x140207600`).
   * Вызывается lookup по `mapInfoList` (`0x1401ba920`), из структуры берется строка `map` (`rbx + 0x50`) и по адресу `0x140207461` выполняется вызов:
     ```nasm
     mov   rax, qword ptr [0x140af33a0]
     lea   rcx, [0x140af33a0]
     mov   rdx, qword ptr [rbx + 0x50] ; mapName
     call  qword ptr [rax + 0x88]     ; GameInstance->ChangeMap(mapName)
     ```

2. **Если `mapDestination == -1` (как у верблюда `Obj_Camel` в Tomb of Ramses):**
   * Движок переходит на ветку `0x1402074d5`.
   * По направлению поворота актора/игрока (`0x14020755f - 0x140207567`) вычисляется сектор компаса:
     `0 = North, 1 = East, 2 = South, 3 = West`.
   * Из файла `defs/mapInfo.txt` (внутри `PowerslaveEX.kpf`) для `Map_Tomb1`:
     ```text
     Map Map_Tomb1 {
         map             "maps/TOMB.MAP"
         nextmap_east    Map_Karnak
     }
     Map Map_Karnak {
         map             "maps/KARNAK.MAP"
         ...
     }
     ```
   * Верблюд ориентирован на восток (сектор 1, `nextmap_east`), что соответствует `Map_Karnak`.
   * Движок выбирает `Map_Karnak`, находит запись в таблице кампании `mapInfoList` и передает в `ChangeMap` строку `"maps/KARNAK.MAP"`.

### 3. Механизм выгрузки и загрузки уровня движком (без выхода в меню)

Переход между уровнями управляется главным циклом состояний `FUN_1401b6480` (RVA `0x1b6480`):
1. **`ChangeMap(instance, "maps/KARNAK.MAP")`:**
   * Устанавливает `*(instance + 0x28) = 4` (`GS_CHANGELEVEL`).
   * Копирует имя карты в `instance + 0x1e0` (`pendingMap`).
2. **Окончание затухания:**
   * По завершении фейда `FUN_1401b6480` переносит значение:
     `*(instance + 0x20) = 4` (`pendingGameState = GS_CHANGELEVEL`).
3. **Выгрузка старой карты (`StateExit`):**
   * Так как `currentState (3, GS_LEVEL) != pendingGameState (4)`, вызывается `0x1401b6670` (`StateExit`).
   * В ветке `case 3` `StateExit`:
     * Сохраняются персистентные данные игрока (`FUN_1401b5b80`).
     * Очищаются звуки и активные акторы.
     * Вызывается нативная выгрузка карты: `kexSlaveLevelLocal::UnloadMap` (`0x1401c90e0`, RVA `0x1c90e0`).
     * Очищаются внутренние кучи `0x140af4490` и `0x140af4600`.
   * **Движок НЕ выходит в главное меню**, поскольку состояние меняется не на `GS_TITLE (1)`, а на `GS_CHANGELEVEL (4)`.
4. **Загрузка новой карты (`StateEnter`):**
   * `*(instance + 0x24) = 4` (`currentState = GS_CHANGELEVEL`).
   * Вызывается `FUN_1401b6a00` (`StateEnter`), ветка `case 4`:
     * Вызывается `kexSlaveLevelLocal::LoadMap` (`0x1401c7b70`, RVA `0x1c7b70`) со строкой `instance + 0x1e0` (`"maps/KARNAK.MAP"`).
     * `LoadMap` читает бинарный файл карты (`PSM`), загружает геометрию, текстуры, спавнит статические сущности.
     * Восстанавливаются персистентные данные игрока (`FUN_1401b5ce0`).
     * При успехе движок ставит `*(instance + 0x20) = 3` (`pendingGameState = GS_LEVEL`).
5. **Вход в игровой процесс новой карты:**
   * На следующем тике `currentState` становится `3` (`GS_LEVEL`), вызывается `StateEnter(3)`, который запускает `kexPlayLoop`, фоновую музыку новой карты и взводит флаги рендера и симуляции.

### 4. Гипотеза и сценарий сетевой репликации (`MSG_MAP_CHANGE`)

#### Шаги для Хоста (Host):
1. **Перехват инициации перехода:**
   * Установить хук (MinHook) на `kexSlaveGameInstanceLocal::ChangeMap` (`0x1401b54d0`).
   * При срабатывании хука на хосте:
     * Получить `const char* mapName` из `RDX`.
     * Инкрементировать эпоху карты: `++g.mapEpoch`.
     * Сформировать и отправить всем клиентам надежный пакет:
       `MSG_MAP_CHANGE(newMapEpoch, mapName)` (код `0x35`).
     * Перевести хост в фазу ожидания клиентов (`Phase::WaitingForMapReady`).
     * Вызвать оригинальный `ChangeMap(thisPtr, mapName)`, запуская штатный нативный переход на хосте.

#### Шаги для Клиента (Client):
1. **Прием пакета в сетевом потоке:**
   * При получении `MSG_MAP_CHANGE(epoch, mapName)`:
     * Сохранить целевые параметры во флаг: `g.pendingMapChange = true`, `g.targetMapName = mapName`, `g.targetEpoch = epoch`.
     * Пометить состояние гейта карты как `Transitioning`.
2. **Вызов смены уровня в simulation-потоке (`hookTick`):**
   * **Критически важно:** вызов `ChangeMap` **нельзя** делать из рабочего ENet-потока — только из главного потока игры (`hookTick`).
   * В начале очередного `hookTick` при наличии флага `g.pendingMapChange`:
     ```cpp
     using ChangeMapFn = void(__fastcall*)(void*, const char*);
     auto changeMap = reinterpret_cast<ChangeMapFn>(g.base + 0x1b54d0);
     changeMap(instance(), g.targetMapName.c_str());
     g.pendingMapChange = false;
     ```
3. **Реакция хука `hookStateExit` на клиенте:**
   * Когда нативный цикл дойдет до `StateExit`, сработает существующий хук клиента:
     `worldTransition("StateExit")` (строка 636 в [client.cpp](file:///s:/_Vibe_Coding/PowerSlave_Exhumed_Together/PowerSlave_Exhumed_Together_mod/experiments/pse_together/src/native/client.cpp#L636)).
   * Он сбросит локальные привязки актеров старой карты, переведет визуальные прокси в безопасное состояние и остановит старую игровую сессию.
4. **Окончание загрузки новой карты и квитирование:**
   * После того как клиентский движок отработает `LoadMap` и перейдет в состояние `gameplay() == true` (`read<int>(instance(), 0x24) == 3 && read<int>(instance(), 0x28) == 0`):
     * Клиент валидирует идентификатор новой карты.
     * Отправляет хосту пакет подтверждения:
       `MSG_MAP_READY(slotId, targetEpoch)` (код `0x36`).
5. **Возобновление кооп-симуляции:**
   * Хост, собрав `MSG_MAP_READY` от всех подключенных клиентов (или по истечении таймаута синхронизации), отправляет `MSG_WORLD_BASELINE` и возобновляет симуляцию на новой карте.
