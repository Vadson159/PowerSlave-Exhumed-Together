# PowerSlave Exhumed Together — правила для моделей

> Редакция 2026-11-03 (задача S0.1 из [ROADMAP](docs/ROADMAP.md); режимы приёмки добавлены в тот же день). Заменяет редакцию времён M0/C05; она сохранена без изменений в [docs/research/AGENTS_before_S0.1.md](docs/research/AGENTS_before_S0.1.md).

## Цель

- 2–8 игроков включая хоста; host-authoritative listen server; LAN/Radmin VPN; ENet.
- Без NAT traversal/STUN/TURN, публичных серверов и matchmaking.
- Независимые состояния игроков, общий сюжетный прогресс, Shared Achievement Progress для всех 20 оригинальных Steam-достижений с учётом участия в событиях.
- Опции предметов, Power-Ups, FF, respawn и scaling — только точки расширения, подробно сейчас не разрабатывать.

Если работа задела память, время жизни объектов, выгрузку, протокол, Steam или оригинал вне принятого шаблона, режим поднимается до В.

## Принятые архитектурные решения

Пересматривать только через ADR и решение пользователя.

- Хост авторитетен. Удалённые игроки на хосте — Full Player: нативные Player/Puppet, которыми управляет ввод клиента ([DOC-27](docs/27_M0_COMPLETION_REPORT.md)).
- На клиенте удалённый игрок — визуальный прокси (пассивный Actor); полный Player на клиенте не создавать ([DOC-54](docs/54_WORLD_REPLICATION_MVP_READINESS.md)).
- Lockstep отвергнут: детерминизм закрытого бинарника не гарантирован ([DOC-02](docs/02_ENGINE_ARCHITECTURE.md), [DOC-22](docs/22_KEX_MULTIPLAYER_CRITICAL_AUDIT.md)).
- Wire v1.10 заморожен ([DOC-29](docs/29_ENET_FINAL_ACCEPTANCE.md)); менять только новой версией протокола (например, v1.11) по отдельному решению.
- D2/D3 приняты пользователем 2026-11-04 через делегирование выбора: A (авторитет хоста с локальным предсказанием без replay) и W1 (реплики мира клиента). D10: поля П6 — в отдельной будущей v1.12, без расширения v1.10 и identity-only v1.11. Выбор архитектуры не закрывает native/runtime gates П7/П9 ([решения](docs/evidence/m1/P6_ADR_REV3/DECISIONS.md)).

## Разрешено

- Runtime-эксперименты, диагностические инструменты, C++ исходники, экспериментальные DLL и сетевой код (ENet) — только внутри этой папки и в отдельных тестовых копиях игры и профилях. Постоянное разрешение на сетевой код подтверждено пользователем 2026-11-03.
- Запуск и instrumentation — только проверенной копии игры в рабочей папке, со свежим профилем и пройденным isolation gate.
- Прогоны в игре — через принятый стенд: REA MCP (Frida) и DLL-loader DOC-51 (см. ROADMAP, приложение A).
- D5 принято пользователем 2026-11-04: для П24 разрешён новый Proxy-DLL загрузчик `pe-together.dll` (SDL2 shim); запрет на новый инжектор снят. Проба нового загрузчика — в тестовых копиях, с прежней REA-защитой профилей и isolation gate; Frida не должна выполнять загрузку DLL. Независимая приёмка загрузчика — режим В.
- D3b принято пользователем 2026-11-04: узкий native Remove подтверждённой MAP-реплики клиента только после class gate П9, с актуальными provenance/поколением, выключенным gameplay, надёжным событием хоста и открытым Sim gate, вне unload barrier. Не разрешены массовое удаление, ручная очистка refs/target/SourceOwner/deletion flags или free; retirement/arena teardown должен наблюдаться отдельно ([границы](docs/evidence/m1/P6_ADR_REV3/DECISIONS.md)).

## Запрещено

- Изменять оригинальную установку (`S:\Games\SteamLibrary\steamapps\common\PowerSlave Exhumed`), пользовательские сохранения и референсы (`S:\_Vibe_Coding\PowerSlave_Exhumed_Together` вне этой папки) — только чтение.
- Изменять Steam-достижения и вызывать их выдачу — до решения пользователя D4 (ROADMAP §6).
- Чинить REA MCP нельзя. Новый загрузчик/инжектор разрешён решением D5 только внутри разрешённой рабочей области; оригинальная установка и пользовательские сохранения остаются только для чтения.
- memcpy игровых структур, произвольная запись указателей, ручная правка refs/target/SourceOwner/флагов удаления, глобальные проходы очистки целей. Remove — только для собственного подтверждённого Actor либо конкретной MAP-реплики в принятых узких границах D3b после class gate П9. Использовать доказанные native lifecycle contracts ([M0_TO_M1_HANDOFF](docs/M0_TO_M1_HANDOFF.md)).
- Повторять принятые исследования, прогоны, широкий реверс и идентичные неуспешные вызовы без изменения условий.
- Выдавать exit0, компиляцию, мок-тесты, рендер второй копии или два выделенных объекта за runtime-приёмку.

## Доказательства и метки

- VERIFIED — проверенное статическое наблюдение с конкретным Evidence; RUNTIME OBSERVED — наблюдение в игре; INFERRED — вывод или гипотеза; UNKNOWN — не установлено.
- Статическое наблюдение не доказывает поведение во время исполнения. Псевдокод декомпилятора не является исходным кодом. Исходники PowerSlave EX 2015, SlaveDriver, PSEPSX и Raze — не исходники KEX 2022. Кооп-мод 2015 года — lockstep на Kex3, из него переносятся только правила ([DOC-33](docs/33_OPUS_COOP_SOURCE_CRITICAL_REVIEW.md)).
- Целевой EXE: SHA-256 `b8f131037187ca8d0a282527fb6f55a2012241d5b9dac8bf2038baf35b71a76d`. Сверять перед каждым прогоном; сохранённые результаты переиспользовать при совпадении хеша и профиля анализа.
- Для функций указывать SHA-256 бинарника, VA/RVA/file offset отдельно, Evidence, наблюдаемые связи, ограничения, неизвестные аргументы/ABI и значение для кооператива. Имена аналитика отделять от восстановленных имён. Никаких вымышленных адресов, полей, сигнатур или подтверждений работы.

## Где что лежит

- Исходники, сборки, профили: `experiments/m0/` (M0), `experiments/m1/<этап>/` (лаборатории M1, заморожены), `experiments/pse_together/` (единый код с S0.3: роли, флаги, все offline-наборы одной командой — [README](experiments/pse_together/README.md)). - Сохранять raw logs, ошибки, выводы и точное воспроизведение каждого опыта.
