## 1. Что принято по ADR-1

[Независимый DOC-75](75_P6_INDEPENDENT_REVIEW_ASTRA.md) отверг редакцию 2 по A1: отсутствие пары после reset могло немедленно порождать новый reset при допустимой задержке и нулевой ошибке позиции. В редакции 3 проверен весь переход `WAIT_ANCHOR → WARMUP_HISTORY → TRACKING`, а не только успешные отдельные формулы.

| Условие | Независимый вывод по T2/T3/T5/T5a |
|---|---|
| Seed и начало поколения | Seed — фактически прочитанное состояние после native apply, с реальным локальным `t_install`, C=0. Старое host stateTime не становится вымышленной локальной записью. `generationStart` не сдвигается при вытеснении seed. |
| Ранний sample | `tau−u < generationStart` отбрасывается во всех фазах, включая TRACKING. Нет повторного anchor, нового token или продления deadline. Равенство левой границы допустимо. |
| Недостающая правая граница | Один pending DTO сохраняется до положительного post-step/покрытия interval; новые пакеты его не вытесняют. Одинаковые timestamps не образуют пару. Pending проверяется до новых samples; максимум одно сравнение за шаг. |
| Два watermark | Приём и сравнение имеют разные границы. Поток более новых отброшенных samples продвигает highestSeen, но не запрещает однократное сравнение ранее принятого pending. Повтор pending не применяется. |
| Непрерывность | Требуется покрытие всего `[tau−u,tau+u]`, не одной точки tau. Уже известный внутренний gap не скрывается ожиданием правой границы. Перед сравнением pending учитывает рост uncertainty. |
| Истинное вытеснение | До начала поколения — drop; внутри поколения, но раньше retained history — настоящий reset в TRACKING, bounded failure при начальном заполнении. Эти случаи различимы даже после удаления seed из кольца. |
| Ограниченное ожидание | Warmup deadline привязан к первой установке, pending deadline — к первому приёму. Трафик не продлевает их. Истечение закрывает соединение без автоматического нового resetToken; обычный пакет не открывает его снова. |
| Новый разрыв/чужое поколение | Неверная identity/token и старый discontinuity не меняют watermark/pending. Подтверждённый новый разрыв начинает новый handshake и очищает старую history. |

Обе временные трассы DOC-75 проверены заново как новые scalar-сценарии. При установке в 40 ms sample с tau=32 ms отбрасывается, пригодный более поздний sample сравнивается с e=0 без нового token. При установке в 1 ms и первом post-step в 17 ms sample tau=16±1 ms получает пару `[1,17]`. Запрет публикации до ACK сохранён, но закрытие A1 также опирается на seed/floor/WARMUP после ACK.

T3 проверен отдельно от HistoryFixture: при фактическом сдвиге 0/5/10 старые и новые записи приводятся к одной системе учёта; новая ошибка 10/5/0 заменяет невыполненный остаток. Pending не фиксирует ошибку до фактического сравнения. Replay и перенос отброшенного движения не добавлены. Нелинейная коллизия, недоказанный d, иная опора/сектор остаются причинами T5 по T4. Старый anchor не ставится повторно; новый действительный разрыв проверяется до его дедупликации.

Это согласованный проектный контракт. Scalar-модель не реализует native apply, транспортные clock/age gates, реальные collision caches или ingress anchor; их отсутствие в fixture не выдано за доказательство игры. Численные latency/u/history/timeouts и реальные post-tick hooks остаются П7.

## 2. ADR-2: сохранность ранее принятого контракта

В сравнении с проверенным DOC-75 snapshot редакции 2 **§4.3–4.6 и §4.8–4.10 совпадают дословно**. Граница D3b и следующий lifetime-абзац совпадают дословно после замены заголовка «Предлагаемая» на «Принятая». [Полная delta ADR-2](evidence/m1/P6_REV3_ACCEPTANCE_SOL/ADR2_DELTA.diff) содержит только принятие W1/D3b и ссылку на решение пользователя; разрешающие safety-условия не ослаблены.

Сохранены R2 capture конкретного фабричного вызова/current activation, отдельные C1/M1, полный baseline, подавление gameplay и запрет scan-only provenance. Remove разрешён только конкретной допущенной MAP-реплике после class gate П9, при точной identity/активации, надёжном deduplicated событии хоста, на Sim TID и вне unload barrier. Remove не доказывает retirement. Неизвестные holders оставляют связь pending; refs-clear/free и повторное использование памяти/ID модом запрещены, контекст остаётся pinned.

Ответы нативному оппоненту DOC-62 §8 переиспользованы в прежних пределах: подавление должно охватывать вложенные touch/sector/use/damage/frame paths; рецепт визуального Actor не доказывает коррекцию Full Puppet; базовый Actor update нельзя считать чистой презентацией; отсутствие AI/scripts не доказывает отсутствие holders. В редакции 3 нет новых native свидетельств, снимающих эти UNKNOWN. Для движения это gates П7, для класса/Spawn/suppression/provenance/retirement — П9. Требовать их реализации внутри П6 оснований нет.
