# DOC-34 — Практический handoff для Sol Max (M0)

**От:** Claude Opus 5.5, 2026-11-01. **Основание:** [DOC-33](33_OPUS_COOP_SOURCE_CRITICAL_REVIEW.md) — пути, строки и статусы там. **DOC-32 этим документом заменяется; его чек-лист «C14» не использовать.**

Исходники «Co-Op Edition» — это lockstep-мод на PowerSlave EX (Kex3, x86), написанный 2026-10-04…05. Это не KEX 2022 и не runtime-доказательство для 2022. Ниже переносятся только правила, которые Sol проверит нативно.

## 1. Можно использовать сразу (как правила анализа, не как код)

1. **Удерживаемый удалённый объект — штатное состояние.** В Kex3 `Remove()` не трогает refcount. Держатель отпускает ссылку только в своём `OnRemove`/деструкторе, когда сам уходит.
   - Критерий приёмки retire: refs → 0 через ограниченное время после ухода держателей.
   - Пока держатели живы, статус — `pending`, а не fail и не повод для ручного ремонта.
2. **Снаряд держит стрелка и не отпускает его заранее.** Это совпадает со статикой Sol для `0x1d50b0` (`proj+0x28 = shooterNode`).
   - Остаточный refs врага при живом снаряде ожидаем.
   - Решение — дождаться ухода снаряда, а не обнулять `+0x28`.
3. **Перечень возможных держателей node в Kex3:** цель AI, стрелок снаряда, цель самонаведения, огни горения (ручной AddRef), поджигатель, динамический свет, **звуковой источник**.
   - Если refs не совпадает с известными рёбрами, ищите держателя этих классов, прежде чем подозревать порчу памяти.
4. **Циклы ссылок.** Два удалённых объекта, держащие друг друга, в Kex3 не освобождаются до выгрузки карты. Если такое встретится, фиксировать как цикл, а не чинить вручную.
5. **Изоляция смерти** делается защитой единственной точки вызова глобального перезапуска. Тело и мир при этом не трогаются. C13 уже применил это к P2 (пропуск нативного update мёртвого P2).
6. **Респавн без «tiny player»:** после пересоздания проверять поля камеры и высоты глаз у **Player**, а не только у Puppet. В 2015 эти поля жили в `kexPlayer`.

## 2. Требует нативной проверки (не объявлять готовым)

| Гипотеза | Статус | Как проверить |
|---|---|---|
| basic projectile освобождает `+0x28` при собственном retire | UNKNOWN | Статически: декремент `[this+0x28]+0x40` в его деструкторе `vtable[5]` / `0x1d32f0`. Runtime: refs врага уменьшается при `pool_return` снаряда |
| AI сбрасывает цель при смерти цели | UNKNOWN | Смерть P2 от реального врага; наблюдать `enemy+0x28` и refs P2 без вмешательства |
| Звук держит node | INFERRED | Статика функций воспроизведения звука (`lock inc [node+0x40]`); runtime: refs 1, исчезающий через 1–3 с |
| `SetSourceOwner 0x1a17c0` (RDX=null) работает в runtime | Статика VERIFIED (C08), runtime **не выполнялся** (C08, C10) | Только actor-impact с наблюдённым impact, после возврата нативного `Remove`, один вызов, `delta == -1` |
| Respawn через нативный `Reset` даёт мачете и пистолет | UNKNOWN | Сравнить оружие и патроны P2 после `Reset`/`Spawn` со стартовым набором |
| Смерть **P1/хоста** без перезапуска карты | Не тестировалось | Найти вызов `GameInstance` в ветке смерти `PlayerUpdate` и выбрать минимальный gate, сохранив камеру и HUD хоста |

## 3. Опасные или ошибочные рекомендации Gemini (DOC-30…32) — не выполнять

1. **«0x160 = kexFireballFactory/GameObject» — INCORRECT.** У Sol `basic_projectile` — это сам снаряд из `SpawnProjectile 0x1d50b0`. `kexFireballFactory` в Kex3 — таймер ловушки сектора. Верно только собственное правило Sol: 0x160 не передавать в Actor Remove.
2. **Удаление ручной установкой `bStale`/флагов `0x2004` — DANGEROUS.** Нативный Remove ещё ставит node в очередь `DAT_140af3380`; переопределённый `Remove` подклассов чистит внешние сырые указатели. Удалять только своим виртуальным Remove.
3. **`SetSourceOwner(nullptr)` для всех снарядов «до Remove» — DANGEROUS.** У объекта 0x160 по `+0x148` лежит чужое поле; вызов сделает `lock xadd` по мусорному адресу.
4. **Сканировать снаряды и обнулять их ссылку на погибшего — DANGEROUS.** `+0x28` — это стрелок, а не цель наведения. Сброс ломает атрибуцию и проверку стрелка, возможен null-deref.
5. **Двухпроходный `SetTarget(NULL)` по всем объектам «при выходе P2» — DANGEROUS.** Это механизм выгрузки всего мира: он сбрасывает агрессию всех врагов и не гарантирует refs 0 (homing, огонь и звук не снимаются; при refs≠0 объект утекает).
6. **«PF_DEAD + DeadMove достаточно» — INCORRECT.** В 2015 перезапуск вызывал цикл уровня, а не DeadMove. Аналог DeadMove в 2022 не найден.
7. **Спектатор, перезапуск при гибели команды, снимки инвентаря — противоречат правилам проекта.**
8. Утверждения «C10 refs=1», «Sol наблюдал краш», «криптографическое доказательство», «WORKING-EVIDENCED» — неверны.

## 4. Какие блокеры M0 можно сократить

- **Enemy refs1 после боя.** Это не блокер корректности, а ожидаемое отложенное освобождение (п. 1.2). Достаточно наблюдать уход держателя. Вмешательство через `SetSourceOwner` — опционально и только по п. 2.
- **Смерть P2 (C13).** Сырые события показывают 2 цикла: смерть → 90 тиков изоляции → retire → пересоздание в том же контексте, refs0, P1 цел. Нужно оформить `RESULT.md` и запись в DOC-27/PROGRESS, а не повторять опыт.
- **Teardown карты.** Не строить свой двухпроходный цикл. Сначала пассивно наблюдать нативную выгрузку с живым P2 (п. 5.4).

## 5. Конкретные эксперименты (по одному на свежий запуск)

1. **Статика без запуска:** проверить, освобождает ли деструктор `vtable[5]` basic projectile (`0x1d50b0` → его класс) / `~kexSlaveObject 0x1d32f0` ссылку `+0x28`. То же — для звука.
2. **Пассивное освобождение держателя:** враг стреляет по P2; ничего не обнулять. Записать: refs `enemy.node` во времени, `pool_return` снаряда, снятие refs. Успех: refs 0 без ручных вызовов в пределах N тиков после ухода последнего снаряда.
3. **Смерть P2 от реального врага:** P2 гибнет от атаки AI, update мёртвого P2 пропускается (как в C13). Наблюдать `enemy+0x28 → P2.node` и refs P2. Затем респавн по сценарию «E»: `Reset`/`Spawn` в стартовой точке уровня; проверить оружие (мачете и пистолет), здоровье, камеру и высоту глаз.
4. **Смерть P1/хоста:** найти и закрыть точку вызова `GameInstance` в ветке смерти; живой P2 продолжает тикать; перезапуска карты нет.
5. **Выгрузка карты с живым P2 (пассивно):** штатная смена или выход в меню при живом P2 и активных снарядах. Наблюдать, что движок сам освобождает node P2 и P1 цел. Ничего не обнулять.
6. Снаряды и патроны P2, направленные коллизии — по плану DOC-27, без изменений.

## 6. Запрещено

- Ручные `lock inc/dec`, запись refcount, флагов удаления, `+0x28`/`+0x148` и указателей в пулах.
- Вызов Actor Remove или `SetSourceOwner` на объекте неподтверждённого класса, включая basic 0x160.
- Глобальные проходы `SetTarget(NULL)` по всем объектам посреди уровня.
- Перенос кода из исходников 2015 (GPLv2-or-later; в репозитории текст GPLv3) в мод.
- Перенос старых игровых правил: спектатор, автоперезапуск, сохранение оружия при смерти, голосовой чат, UPnP.
- Изменение `tools/enet-prototype/`, протокола DOC-29, сети и Steam-достижений в рамках M0.
