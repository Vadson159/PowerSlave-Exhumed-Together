Заметки без дефекта:

- **memcpy заголовка блока.** Копия 0x58 байт заголовка tagged-блока в локальный буфер ([native_proxy_p3.cpp:313,500,551](../experiments/pse_together/src/native/native_proxy_p3.cpp), [teardown_witness_p3.hpp:31](../experiments/pse_together/src/proxy/teardown_witness_p3.hpp)) только читает; в принятой базе есть аналог (`read<std::array<Byte,128>>(player())`). Формально это подпадает под запрет «memcpy игровых структур». Толкование — за владельцем правил, пользователь решает, нужно ли заменить на поэлементное чтение.
- Взведённый, но не выданный Remove не имеет дедлайна: без живого Sweep автомат вечно в RETIRING, отсоединение откладывается (живучесть).
- `levelUnload` без барьера при живом Actor не блокирует адаптер, в отличие от `arenaPurge`; после Unload `sector()` бросает на нулевом указателе.
- Вердикт `LiveAtBarrier` вместе с `IssuedDrained` принимается как штатный путь; по коду недостижимо, но противоречиво.
- Обход списка на выходе purge предполагает, что `c58b0` обновляет `heap+8`; если голова висячая, SEH не поймает чтение освобождённой памяти, а итог — только неверная классификация (`Unknown`, закрытая).
- Детур `level_unload` не передаёт стековые аргументы и XMM0; `emit` после вызова может затереть XMM0. Для `void`-функции без стековых аргументов маловероятно, но не доказано.
- Расхождения форка сверх заявленного: заголовок `client_p3.cpp:6` обещает барьер при Mismatch, а код (`:127`) только пишет журнал; не заявлены повторная попытка старта Session через 60 тиков и обновление терминального ClientGate при новой generation; рост generation хоста считается монотонным (после рестарта хоста — вечный `SessionNotNewer`).

Агент проверил и не нашёл проблем в: четырёх детурах (оригинал вызывается на каждом пути, регистры сохраняются, `actor_dtor` не читает Actor после вызова), условиях вердикта (ложный `ArenaDestroyed` по коду недостижим), условиях выдачи Remove (только `inTick`, `inSweep`, `!stopping`, `p1ThisTick`, `Live`, строгая `actorIdentity`), правилах rearm (закрытый экземпляр не получает session и MapReady; мёртвое закрытие и shutdown необратимы; latch внутри экземпляра не снимается), порядке жизненного цикла клиента (барьер → остановка Session → исходный StateExit → вердикт → удаление → world+1), анти-ABA, и правилах AGENTS.md (записей указателей, правок refs/target/флагов, проходов очистки нет).
