Снаряд держит стрелка до собственного удаления. «Удалён, но удерживается» — штатное состояние; критерий приёмки retire — refs 0 после ухода держателей (`pending`, а не ручной ремонт).
- **`RemoveAllGameObjects`** снимает только рёбра `target` и только при выгрузке всего мира. Объект с refs≠0 он не удаляет, а теряет (утечка). Для частичного удаления P2 не применим. Старый мод вообще не удаляет тело одного игрока посреди уровня.
- **Исправленные ошибки Gemini:** объект `0x160` в M0 — basic projectile из `0x1d50b0`, а не `kexFireballFactory`. Опасны и запрещены: ручные флаги `0x2004`/`bStale`; `SetSourceOwner` на всех снарядах (у объекта 0x160 по `+0x148` лежит чужое поле); обнуление `+0x28` у снарядов (это стрелок); глобальный проход `SetTarget(NULL)` при выходе P2. «C10 refs1» неверно (в C10 оба узла refs0). Чек-лист «C14» не использовать.
- **Изоляция смерти:** в 2015 перезапуск вызывался из цикла уровня, а не из DeadMove. Переносится только принцип защиты точки вызова. C13 уже изолировал смерть P2 (пропуск нативного update). Смерть P1/хоста без перезапуска карты пока не проверена.
- **Правила проекта:** спектатор, автоматический перезапуск при гибели команды, сохранение оружия при смерти, голосовой чат и UPnP из старого мода не переносятся.
- **Состояние M0:** C13 (смерть и повторное создание P2 в двух циклах, refs0, P1 цел) есть только в сырых событиях — нужны `RESULT.md` и запись в DOC-27. Следующие проверки — DOC-34 §5.

1. `SetTarget` RVA0x1d35d0: Win64 ABI `(kexSlaveActor* this, kexSlaveActor* pTarget)`.
   - При `pTarget == NULL`: читает старый node `[this + 0x28]`, обнуляет `[this + 0x28] = 0`, выполняет `lock xadd dword ptr [oldTargetNode + 0x40], -1` (атомарный декремент refcount).
   - При `pTarget != NULL`: читает `newTargetNode = [pTarget + 0x10]`. Если узел изменился: `[this + 0x28] = newTargetNode`, `lock inc dword ptr [newTargetNode + 0x40]`, и декрементирует refcount прежней цели.
2. `kexSlaveAI::OnDamage` RVA0x195050 (строки 165–177): при получении урона AI устанавливает `[enemy + 0x28] = attackerNode` (`p2.node` 0xc85b7d0) и делает `lock inc dword ptr [p2.node + 0x40]`. Это полностью объясняет удержание ссылки `enemy.target -> P2 node` и `p2.node->refs = 1` после Reset(P2).

Активный снаряд удерживал refcount `enemy.node`.
4. Механизм `RemoveActor` и `Deferred Sweep`:
