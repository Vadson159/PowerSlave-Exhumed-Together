# Переделка синхронизации (ветка `sync-rework`)

Начато 2026-11-11. Ход работы ведёт агент; пользователь проверяет только итог.

## Цель

- Одна сетевая сессия хоста на всю игру (до выхода хоста), клиенты не переподключаются при смене мира.
- Один мир — у хоста; клиент грузит ту же карту, но логику мира не выполняет, а показывает состояние хоста общими каналами.
- Владение: что делает мой игрок (движение, касания, «использовать», урон от окружения, попадания) — решает мой клиент и сообщает хосту; всё остальное — хост.

## Этапы

| # | Этап | Статус |
|---|------|--------|
| 1 | Единая сессия хоста (смена мира = новая привязка карты/epoch внутри сессии) | готов, проверен вживую |
| 2 | Общий перехват действий своего игрока у клиента (касание, «использовать», урон) — один канал | готов, проверен вживую |
| 3 | Общая репликация акторов уровня, локальная логика мира у клиента выключена | готов (3.1), проверен вживую; 3.2–3.4 — решения ниже |
| 4 | Репликация секторов (пол/потолок/свет) и граней (текстуры рычагов) | готов, проверен вживую |
| 5 | Удаление лишних частных пересылок | готов, проверен вживую |
| — | Финал: полный регресс, пакет друга, S:\PSE_Together, отчёт | готов |

## Этап 1 — единая сессия хоста

Сделано в коде:
- `m12a::Session` хоста живёт весь процесс: `unbind("StateExit")` зовёт `leaveWorld()` (все клиенты остаются подключены, но не готовы),
  остановка — только при выходе из игры (DirectQuit) или неустранимом сбое процесса.
- Следующий мир: вместо новой сессии — `rebindNativeMap(identity, новый epoch)`: все HostGate перепривязываются, клиентам уходит
  MapChange с `newMapEpoch != 0` (BROADCAST: рабочий поток сети обновляет карту WELCOME и фильтр epoch снимков).
- Тайм-аут входа (600 тиков без MapReady) считает только тики, когда хост в игре, и только для нового соединения:
  клиент, бывший готовым, не выкидывается, пока грузится или выбирает на карте мира.
- Повторный MapReady того же epoch (мир клиента перезапустился сам, у хоста — нет) = «повторная готовность»: базовая линия и общее
  состояние мира (joinSerial) заново, тело у хоста продолжает жить.
- Сервер: слот давно ушедшей личности (отключена > 60 с) отдаётся новичку (поколение слота растёт дальше); короткий обрыв слот держит.
- Клиент: `ENetClientNode::setSessionMap` при MapChange нового epoch (фильтр снимков), ввод ждёт MapReady нового мира.
- Клиент: Session переживает `worldTransition` (если соединение живо): сбрасываются только мировые защёлки (прокси, респаун P16, P7),
  `ClientGate::newWorld()`; новая привязка хоста (`ClientGate::mapChange`) — без блокировки; несовпадение уровня с хостом больше
  не терминально — клиент следует за уровнем хоста (`followCheck`: один раз на новую привязку, чтобы не вернуть клиента назад,
  пока хост сам ещё между мирами). Приказы хоста, полученные до ухода из мира, при уходе отбрасываются.

Проверено оффлайн:
- сборка без предупреждений; ctest 18/19 (`p24_loader_contract` — как всегда);
- `multi_peer_live`: новый раздел 9 (7 клиентов): leaveWorld → 900 тиков вне игры без выкидывания → rebind → у всех MapChange с новым
  epoch в том же соединении → старый MapReady отвергнут, новый принят → базовая линия нового мира → снимки нового epoch доходят →
  ввод → повторная готовность → переподключение после смены мира получает новый мир в WELCOME (170 проверок).

## Этап 2 — один канал для действий своего игрока у клиента

Сделано в коде:
- `ReqTouch = 0x1c` (вид касания + номер актора на проводе): ВСЁ, чего коснулся свой игрок у клиента через родные OnTouch движка —
  шары здоровья/патронов (`TouchHealth/Ammo`), ключи (`TouchKey`), оружие (`TouchWeapon`, новый хук клиента 0x1d8470), скарабеи
  (`TouchScarab`) — уходит хосту одной очередью `pushTouch` (повтор того же актора не чаще раза в 30 тиков).
- Хост: `applyTouch` — тело этого игрока касается того же актора родным OnTouch (шары через P14 этому игроку с прежней проверкой
  расстояния; ключ — в общий набор ключей; оружие — через P16, остаётся в мире для других); скарабей — `markCheckpoint16(slot)`.
- Клиент больше не шлёт ReqPickup / ReqCheckpoint / ReqKeys (обработчики у хоста пока оставлены — снимаются на этапе 5).
- «Использовать» (E) и урон уже идут через общие точки движка: E — кнопкой ввода тела (фронты `takeNativeEdges`), урон — общий хук
  Damage 0x1a1370 (ReqHit по врагам, ReqSelfDamage — окружение); отдельных пересылок под механики здесь нет.
- Отладка: `PSE_DEBUG_TOUCH_CLIENT="вид,номер[;...]"` + `PSE_DEBUG_TOUCH_FILE` — свой игрок клиента касается актора карты через
  перехваченный родной вход OnTouch. (Скарабей родным OnTouch проверяет прямую видимость — издалека не отмечается; проверяется проходом.)

Проверено вживую:
- `smoke_s2` (KARNAK): ключ 219 — клиент коснулся родным OnTouch → ReqTouch → тело у хоста взяло ключ → общий набор ключей 4 у всех.
  Шар 42 издалека — хост отказал по расстоянию (как задумано). `SMOKE_S2_TOMB=1`: оружие 48 — тело клиента у хоста получило пистолет (P16).
- Регресс после этапа 2: `smoke_m9` (скарабей 235 проходом → ReqTouch вид 4 → у хоста слот 1; респаун у своего скарабея; восстановление
  после сбоя; 1 welcome), `smoke_m7` (шар 42 проходом → ReqTouch вид 1 → взят телом, отклик подбора у клиента), `smoke_s1` 21/21,
  `smoke_n 3` + смена уровня — всё PASS; журналы без проблем и застреваний; ctest 18/19.

## Этап 3 — общая репликация акторов

Что уже было до переделки (остаётся основой): враги (`collectEnemies`/`applyEnemies`, тип 1, 20 Гц, ИИ клиента заменён репликой —
хук AiTick), снаряды врагов (тип 2, каждый тик, локальные снаряды клиента гасятся), порождённые враги/шары (тип 3, список `DynTypes`,
локальные случайные выпадения клиента гасятся `cullLocalDynamic`), платформы/площадки (тип 4), смерть врага у клиента родным путём.

Сделано на этапе 3:
- Шаг 3.1 (код готов, проверка `tools/smoke_s3.py`): «актор карты исчез у хоста» — для ЛЮБОГО класса, а не только врагов: хост
  каждые 3 тика (и один, до входа клиентов) отмечает все акторы карты (номер +0x180 >= 0), кроме тел игроков и касаемых предметов
  (флаг 0x100: оружие/анкхи/артефакты каждый игрок берёт сам, шары — EvPickup, ключи общие); пропавший уходит EvEnemyGone (всем сразу и
  каждому вошедшему позже), клиент убирает тот же актор родным Remove. Очередь не теряет пропавших при переполнении.
  Отладка: `PSE_DEBUG_REMOVE="номера"` + `PSE_DEBUG_REMOVE_FILE` (хост убирает акторы карты родным Remove).

- Попутно: HUD-перехваты (6 MinHook) ставятся одной пачкой (`MH_QueueEnableHook` + один `MH_ApplyQueued`) и у хоста — в начале уровня,
  до входа клиента (`prepareHud`): вход клиента больше не стоит хосту ~0,2 с тика (было при каждом первом входе за процесс).

Проверено вживую (после 3.1): `smoke_s3` 5/5 — хост убрал 7 акторов карты разных классов (факелы/декор 0x48, вазы 0x1000026/0x100006a),
у клиента убраны все 7 (`world_enemy_gone_applied found ai=false`); `smoke_m7`, `smoke_s1` 21/21, `smoke_n 3` + смена уровня — PASS;
log_check: проблем нет, застреваний тика в игре нет (0). ctest 18/19.

Решения по остальному (после разбора кода, без изменений поведения):
- 3.2 порождённые акторы: список `DynTypes` (враги из ваз/смертей, шары, вспышки) остаётся «разрешающим»: глушить у клиента ВСЕ свои
  порождённые акторы нельзя — это и эффекты своих выстрелов/попаданий (искры, кровь, гильзы), их видит только сам игрок. Новый тип
  добавляется в список, когда найден реальный расхождение в игре.
- 3.3 состояние неигровых акторов карты: у хоста меняются только вазы (EvBreak), рычаги (грани, этап 4), двери/лифты/платформы (секторы,
  этап 4), враги (уже). Отдельный снимок не нужен.
- 3.4 локальная логика клиента: ИИ (реплика), снаряды врагов, случайные выпадения — уже выключены; сюжетные скрипты: клиент запускает
  только свои (свой игрок пересёк триггер — это действие своего игрока, ReqScript), чужие — по EvScript хоста; тики механизмов — этап 4.

## Этап 4 — репликация секторов

Сделано в коде:
- Хост (тип 5 в снимке мира): каждый сектор, который в этом мире хоть раз двигался, — пол/потолок (высота плоскости +0x68/+0x70 → +0x18)
  4 раза в секунду; сейчас движущиеся (флаг сектора +0x14 & 4) — 20 раз в секунду.
- Клиент (`applySectors`): доводит свой сектор до высот хоста родным сдвигом плоскости `0x1ce510(сектор, потолок?, дельта)` — той же
  функцией, которой тики дверей/лифтов двигают пол (dl=0) и потолок (dl=1) вместе с вершинами граней. Не трогает сектор, в котором его
  собственный механизм работал последние 1,5 с: дверь, открытая своим действием или пересылкой, доигрывает свою анимацию и звук, а
  потерянная или разошедшаяся (не та высота, застрявший лифт) — сходится к хосту.
- Грани (текстуры рычагов): остаётся EvSwitch — родная смена текстуры рычага по номеру грани с выключенным триггером; поздним входящим
  повторяется весь список. Отдельная репликация граней не нужна (других изменений граней во время игры нет).
- Свет секторов: не реплицируется — мигание света у каждой машины своё (локальный эффект), игровых последствий нет.
- Отладка: `PSE_DEBUG_DROP_MOVERS=1` (клиент игнорирует пересылку дверей/лифтов EvMover).

Проверено вживую: `smoke_s4` 5/5 — хост открыл первую дверь TOMB (сектор 33), клиент без пересылки (`DROP_MOVERS`) поднял потолок
сектора 33 вслед за хостом (-256 → … шаг 12, 20 раз/с), `world_mover_applied` у клиента нет. Журналы чистые.
Регресс после этапа 4: smoke.py INPUT (дверь по E клиента: открыта у обоих, коррекций у клиента 0 — локальная анимация не перебита),
smoke_m9, smoke_s1 21/21, smoke_n 3 + смена уровня — PASS; журналы чистые, застреваний в игре нет; ctest 18/19.

## Заметки разведки для этапа 2 (EXE b8f131…, RVA)

- Общая точка касания актора: `0x1a4990(rcx, Actor* mover = rdx, r8)` — проход по акторам секторов при движении `mover`.
  Внутри (`0x1a596f`) берёт флаги касаемого `+0x16c` (0x2 solid, 0x100 touchable), проверка расстояния, затем
  `0x1a5a84: mov rax,[rbx]; mov rdx,r15; mov rcx,rbx; call [rax+0x40]` = `touched->OnTouch(mover)`.
  Вызывающие: `0x19f2d0` (физика актора, 0x19f7ed), `0x1a1530`, `0x1dc6e0`, `0x1dd670`, `0x1ddf70`, `0x1de8b0`.
- Сам вызов виртуальный: перехватывать либо входом `0x1a4990` (область «двигается свой игрок») + детуры реализаций OnTouch
  (+0x40 классов с флагом 0x100, известные: здоровье 0x1d8770, патроны 0x1d8590, скарабей 0x1a3b50, ключ/оружие/анкх — vtable 0x52c998/0x52cb60/0x52c7d0).
- Инструменты разведки: `tools/re/xdis.py <rva> [n]` / `xdis.py find <regex> [window-regex]` и `tools/re/xfunc.py <rva>...` (capstone+pefile; EXE play_vote).
- OnTouch (+0x40) по vtable: здоровье 0x52c868→0x1d8770, патроны 0x52cac8→0x1d8590, анкх 0x52c7d0→0x1d8870, ключ 0x52c998→0x1d8a00,
  оружие 0x52cb60→0x1d8470, скарабей 0x5288f0→0x1a3b50, выход TravelObject 0x530588→0x2072e0, Puppet игрока 0x52d198→0x4a670 (базовый, пустой?).
